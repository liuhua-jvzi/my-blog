# 第五章-查找

&emsp;&emsp;查找就是**在一堆数据里找到某个指定的关键字**。数据可能存在数组、链表、树、哈希表里，本章学 4 种查找方式：**顺序查找、二分查找、二叉排序树查找、哈希表查找**。它们的区别全在于**数据存在什么结构**、**查找过程快不快**。

## 一、先认识几个词

| 名词 | 一句话 |
|------|--------|
| key | 你要找的那个值（关键字），比如找 50，key = 50 |
| ASL | Average Search Length，平均查找长度；大白话 = 平均要比较多少次才能找到 |
| 时间复杂度 O(n) | 最多扫一遍整个表 |
| 时间复杂度 O(log n) | 每次砍半，很快 |

> 本章**数组下标统一从 0 开始**（C 语言习惯，教材默认写法）。

## 二、顺序查找（最基础）

**怎么做：** 从头到尾一个个比，找到就停；全比完了还没找到就说没有。

**它能用在什么地方：** 什么结构都行——顺序表、单链表，甚至一堆没排好序的数据。**唯一要求：你能一个个遍历到。**

### 存储结构对比

| 存储结构 | 顺序查找能行吗？ | 额外代价 |
|----------|-----------------|---------|
| 顺序表（数组） | ✅ 能 | 插入删除要整体移动元素 |
| 单链表 | ✅ 能 | 查找必须从头扫，不能跳 |

### ASL 公式（等概率情况下）

> **等概率** = 假设每个元素被查找的可能性一样，都占 1/n。

**成功查找的 ASL：**

```
ASL 成功 = (1 + 2 + 3 + ... + n) / n = (n + 1) / 2
```

意思是：找第一个元素比 1 次、找第二个比 2 次…找最后一个比 n 次，加起来除以 n 就是平均。比如 n=10，ASL = (10+1)/2 = 5.5。

**失败查找的 ASL：**

```
ASL 失败 = n + 1
```

意思是：必须扫完整个表（n 次）才知道没有，最后还要做一次判断，所以是 n+1。

### 时间复杂度

| 情况 | 时间复杂度 |
|------|-----------|
| 最好（第一个就是） | O(1) |
| 平均 | O(n) |
| 最坏（最后一个才是，或根本没有） | O(n) |

### 什么时候用

数据量不大（几十个）、或者数据没排好序、或者存放在链表里——顺序查找最简单，好写好懂。

## 三、二分查找 / 折半查找（重点）

**核心思路：** 每次看**中间那个元素**，比它大就砍去左半区，比它小就砍去右半区。**每次把范围砍半**，所以非常快。

### 前提条件（两个条件必须同时满足）

1. **顺序存储**（存在数组里）—— 因为二分查找要通过下标直接跳到中间位置 `mid`，链表做不到按下标直接访问。
2. **按关键字有序**（升序或降序都行，方向要统一）—— 只有有序，才能确定"比中间大就一定在右边"。

> ❌ 链表**不能**用二分查找，哪怕链表里的数据是排好序的也不行。
> ✅ 数组里**没排好序**也不能用，必须先排序。

### low / high / mid 是什么

这三个变量**贯穿整个二分查找**，必须搞清楚：

| 变量 | 含义 | 初始值（下标从 0 开始） |
|------|------|------------------------|
| **low** | 当前搜索区间的**左边界**（最左边那个元素的下标） | 0 |
| **high** | 当前搜索区间的**右边界**（最右边那个元素的下标） | n - 1（n 是元素总个数） |
| **mid** | 当前区间的**中间位置** | `mid = (low + high) / 2`（整数除法，自动取整） |

### 查找过程（配图画出来）

<DsFigure type="binary-search" />

图里的数组是 `(6, 10, 22, 26, 38, 41, 46, 50, 66)`，共 9 个元素（下标 0~8）。现在要找 key = 50：

```
第一次：low=0, high=8
  mid = (0 + 8) / 2 = 4
  a[4] = 38，比 key=50 小 → 目标一定在右半区
  → 把 low 挪到 mid+1 = 5（砍掉左半区）

第二次：low=5, high=8
  mid = (5 + 8) / 2 = 6
  a[6] = 46，比 50 小 → 继续往右
  → low = 7

第三次：low=7, high=8
  mid = (7 + 8) / 2 = 7
  a[7] = 50 → 找到了！🎉
```

一共比较了 **3 次**。

> **砍半规则就一句话：**
> - `a[mid] == key` → 找到了
> - `a[mid] > key` → key 在左边，**high = mid - 1**（把 mid 排除）
> - `a[mid] < key` → key 在右边，**low = mid + 1**（把 mid 排除）
> - `low > high` → 区间空了，没找到

### 计算公式（必考，直接套）

#### 最多比较多少次能成功

最坏情况（目标不存在或在最边缘）需要比较的次数：

```
成功查找的最大比较次数 = ⌊log₂n⌋ + 1
```

其中 `⌊log₂n⌋` 是向下取整，比如 `⌊log₂9⌋ = ⌊3.17⌋ = 3`，所以 n=9 时最多 3+1=4 次。

或者另一种写法（层数算）：

```
⌈log₂(n + 1)⌉
```

两种写法**结果相同**。比如 n=9，`⌈log₂10⌉ = ⌈3.32⌉ = 4`，和上面一样。

#### ASL（等概率）

二分查找的成功 ASL 没有一个特别整齐的闭式公式，但**近似值**很好记：

```
ASL 成功 ≈ log₂(n + 1) - 1
```

精确计算时，用**判定树**来算最直观：

<DsFigure type="bst-binary-search" />

判定树里，**每个结点的层数 = 找到这个元素需要比较的次数**。所以：

```
ASL 成功 = Σ (每层的结点数 × 层数) / n
```

比如 n=9，判定树第 1 层 1 个结点、第 2 层 2 个、第 3 层 4 个、第 4 层 2 个：

```
ASL = (1×1 + 2×2 + 3×4 + 4×2) / 9
    = (1 + 4 + 12 + 8) / 9
    = 25 / 9 ≈ 2.78
```

#### 失败 ASL

失败查找时，判定树里走到了"空"的位置（比如图里的叶子位置 0 和 ×），需要比较次数大约是 `log₂(n + 1)`：

```
ASL 失败 ≈ log₂(n + 1)
```

> 题库 62 题说"最坏情况需要 O(log n) 次"是对的——这正是二分查找比顺序查找好的地方，顺序查找最坏 O(n)。

### 时间复杂度

| 情况 | 时间复杂度 |
|------|-----------|
| 最好（mid 刚好就是） | O(1) |
| 平均 | O(log n) |
| 最坏 | **O(log n)**（比顺序查找好太多） |

### 例题

**题库 59 题：** 有序表 (25, 38, 63, 74)，找 25 比较几次？

```
n = 4，low=0, high=3
mid = (0+3)/2 = 1
a[1]=38 > 25 → high=0

low=0, high=0
mid = 0
a[0]=25 → 找到

一共比较 2 次。但答案给的是 A（3 次）—— 因为有些教材用 ⌈log₂(n+1)⌉，n=4 时 ⌈log₂5⌉=3，
这是理论最大值。实际跑了正好 2 次，但选项里没有 2。
这题选 A。
```

**题库 60 题：** 12 个关键字等概率，ASL 约为？

```
判定树形状（n=12）：
第 1 层：1 个
第 2 层：2 个
第 3 层：4 个
第 4 层：剩余 5 个

ASL = (1×1 + 2×2 + 3×4 + 4×5) / 12
    = (1 + 4 + 12 + 20) / 12
    = 37 / 12 ≈ 3.08

选项 B 是 38/12 ≈ 3.17，最接近，选 B。
```

**题库 72 题：** 长度 18 的有序表，找第 1 个元素（下标 0），比较几次？

```
n = 18
⌈log₂(18+1)⌉ = ⌈4.25⌉ = 5 次

或者实际走一遍：
mid=9 → a[9]>key → 去左
mid=4 → a[4]>key → 去左
mid=2 → a[2]>key → 去左
mid=1 → a[1]>key → 去左
mid=0 → 找到

正好 5 次。选 B。
```

## 四、二叉排序树查找（BST）（重点）

### 什么是 BST

**二叉排序树**（Binary Search Tree），也叫二叉搜索树。对树里**任意一个结点**，它都满足：

- **左子树所有结点的值 < 这个结点的值**
- **右子树所有结点的值 > 这个结点的值**

有了这个性质，**中序遍历 BST 一定得到升序序列**（中序遍历使它从小到大排序）。

<DsFigure type="bst" />

看上面的例子：根 50，左边的 30、20、40 都比 50 小；右边的 70、60、80 都比 50 大。中序遍历（左 → 根 → 右）：20, 30, 40, 50, 60, 70, 80，正好升序。

### BST 查找过程

和二分查找**逻辑完全一样**，只不过二分查找是在数组里跳下标，BST 是在树上走指针：

```
从根开始：
key == 根结点  → 找到
key < 根结点  → 去根的左子树继续找
key > 根结点  → 去根的右子树继续找
走到空指针    → 没找到
```

### BST 插入规则

**新结点永远是叶子结点**——沿着查找路径走，最后走到 NULL 的地方挂上去就行。插入后 BST 的性质依然成立。

### BST 的效率取决于树的形状

| 树的形状 | 是什么样 | 查找效率 |
|----------|---------|---------|
| **平衡**（接近满二叉树） | 每层塞满，层数 ≈ log₂n | **O(log n)**，和二分查找一样快 |
| **单支树 / 链表退化** | 所有结点只有左孩子或只有右孩子，退化成一条直线 | **O(n)**，和顺序查找一样慢 |

> 题库 58 题：呈**单支树**时，BST 查找效率最低，退化成 O(n)。

**为什么会退化？** 如果插入的数据本身就是有序的（比如 1, 2, 3, 4, 5），每次都往右边插，就会形成一条只有右孩子的"链表"。

### BST 和二分查找的对比

| | 二分查找 | BST 查找 |
|--|---------|---------|
| 存储结构 | **只能是数组** | **只能是二叉链表** |
| 是否需要有序表 | **必须**整个表有序 | 不需要（树结构本身保证有序） |
| 能否动态插入删除 | **不能**（插入删除要整体移动数组元素，O(n)） | **能**（插叶子、替换结点，O(log n) 平均） |
| 最坏效率 | **O(log n)** | **O(n)**（单支树退化） |
| 动态数据推荐 | ❌ 不适合 | ✅ 适合 |

### 时间复杂度汇总

| 操作 | 平均 | 最坏 |
|------|------|------|
| 查找 | O(log n) | **O(n)** |
| 插入 | O(log n) | **O(n)** |
| 删除 | O(log n) | **O(n)** |

> 题库 70 题：BST 查找最坏时间是 **O(n)**，选 D。

## 五、哈希表查找（散列表）（重点）

### 核心理念：直接算地址，理想情况 O(1)

前面三种查找，**再快也得一个个比**（顺序表从头扫、二分每次砍半、BST 走树）。哈希表**连比都不比**——你给我一个 key，我用哈希函数直接算出它存在哪个数组下标里，**一步到位**。

### 三个名词先讲清楚

| 名词 | 大白话 |
|------|--------|
| **哈希函数** H(key) | 把关键字变成数组下标的函数。最常用的是 `H(key) = key % m`（取模），m 是哈希表长度。比如 key=27，m=6，H(27)=27%6=3，存在下标 3 的位置。 |
| **冲突** | 两个不同的 key 算出了同一个地址。比如 27%6=3，15%6=3，那 27 和 15 都想占下标 3 的位置，冲突了。 |
| **装填因子 α** | `α = 表里已存元素个数 / 哈希表长度 m`。α 越大，越容易冲突。一般控制在 **α < 0.8**。 |

### 哈希函数怎么选（了解）

最常用的是**除留余数法**：

```
H(key) = key % m
```

其中 **m 取素数**（比如 7、11、13、101 这种）。m 取素数的好处是 key 分布更均匀，冲突更少。

### 冲突解决方法

哈希表**必须解决冲突**，不然同一个位置存不下两个元素。教材里讲两种：

#### 方法一：开放地址法（所有元素都存在哈希表数组里）

冲突了就**顺着数组往后找**空位：

| 探测方式 | 怎么做 | 优缺点 |
|----------|--------|--------|
| **线性探测** | 冲突了就看 `(原位置 + 1) % m`，还冲突再 +1 +2… | 简单但容易**聚集**——元素连成一串，查找时得整条链扫过去 |
| **二次探测** | 冲突了就看 `(原位置 + 1²) % m`，再冲突用 `(原位置 + 2²) % m`… | 能缓解聚集，但**不能完全避免**（题库 65 题）；而且 m 得是素数，可能找不到空位 |

> 题库 65 题：**二次探测可以避免聚集**这种说法是**错的**。它只能"缓解"聚集，不能"避免"。线性探测一定会出现聚集。

**开放地址法的缺点：** 删除不能直接把数组位置清空（会打断探测链），必须打个"已删除"标记。

#### 方法二：链地址法（最常用）

每个数组位置挂一条**链表**，冲突的元素直接插到链表里。

<DsFigure type="hash-chain" />

图里哈希表长度 m=6，有几个元素：

- 槽 0 空着
- 槽 1 有冲突：27 和 19 都 %6=1，所以挂了一条链表 `27 → 19`
- 槽 2 单独放了 34
- 槽 4 冲突最多：8、14、20 都 %6=4，链表 `8 → 14 → 20`

**链地址法的优势：**
- **冲突再多也不怕**，链可以无限长
- 插入删除简单，直接操作链表
- **不需要"已删除"标记**，删了就删了

**劣势：** 多了链表的指针开销，而且链太长时查找得扫整条链。

### 查找效率（关键公式）

装填因子 α 是**影响 ASL 的核心因素**——α 越小（哈希表开得越大），冲突越少，效率越高。

#### 链地址法

```
ASL 成功 ≈ 1 + α / 2
ASL 失败 ≈ 1 + α
```

意思是：成功时平均只要看 1 次（找到）加上链上的平均长度的一半。α = 0.8 时，ASL 成功 ≈ 1.4，还是很快。

#### 开放地址法（线性探测）

```
ASL 成功 ≈ (1 + 1/(1 - α)) / 2
ASL 失败 ≈ (1 + 1/(1 - α)²) / 2
```

开放地址法对 α 特别敏感——α 接近 1 时，ASL 爆炸增长，哈希表几乎不能用了。

### 哈希表的时间复杂度

| 情况 | 时间复杂度 |
|------|-----------|
| 理想（无冲突） | **O(1)** |
| 平均 | **O(1)** |
| 最坏（全部冲突） | O(n) |

> 平均情况下哈希表查找就是 **O(1)**，这是它比 BST 好的地方——BST 平均 O(log n)，哈希表快一个数量级。

### 什么时候选哪种冲突解决

| 方法 | 适合场景 |
|------|---------|
| 链地址法 | **最常用**，尤其是动态插入删除多的场景 |
| 开放地址法 | 不想用指针、想用纯数组时，但装填因子必须控制得低 |

## 六、四种查找方式大对比

| | 顺序查找 | 二分查找 | BST 查找 | 哈希表查找 |
|--|---------|---------|---------|-----------|
| **存储结构** | 顺序表、链表都行 | **只能数组** | **只能二叉链表** | 数组 |
| **要求数据有序？** | ❌ 不要求 | **必须有序** | ❌ 不要求（树结构保证） | ❌ 不要求 |
| **平均时间** | O(n) | O(log n) | O(log n) | **O(1)** |
| **最坏时间** | O(n) | O(log n) | **O(n)**（单支退化） | O(n)（全部冲突） |
| **能否动态插删** | 链表：能<br>数组：慢 O(n) | **不能** O(n) | **能** O(log n) | **能** O(1) |
| **空间额外开销** | 无 | 无 | 每个结点两个指针 | 链地址法有链表 |
| **典型用途** | 数据量小、不常查 | 数据固定、量大、常查 | 数据动态增删 | **追求最快，最常用** |

## 八、必背公式汇总

### 二分查找

```
最多比较次数（成功） = ⌊log₂n⌋ + 1 = ⌈log₂(n+1)⌉

ASL 成功 ≈ log₂(n + 1) - 1          // 近似值
ASL 成功 = Σ (层数 × 该层结点数) / n  // 精确值（判定树算）
ASL 失败 ≈ log₂(n + 1)
```

### 顺序查找

```
ASL 成功 = (n + 1) / 2
ASL 失败 = n + 1
```

### 哈希表

```
装填因子 α = 元素个数 / 哈希表长度 m

链地址法：
  ASL 成功 ≈ 1 + α / 2
  ASL 失败 ≈ 1 + α

开放地址法（线性探测）：
  ASL 成功 ≈ (1 + 1/(1-α)) / 2
  ASL 失败 ≈ (1 + 1/(1-α)²) / 2
```

### BST

```
平均 ASL ≈ 1 + 4lnn / 3    （随机插入情况下）
最坏 ASL = n               （单支树退化）
```
