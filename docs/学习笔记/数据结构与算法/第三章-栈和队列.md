# 第三章-栈和队列

栈和队列都是**操作受限的线性表**：栈像一堆盘子，后进先出；队列像排队买饭，先进先出。

## 一、栈（Stack）

### 1. 是什么

栈只允许在**一端**插入和删除，这一端叫**栈顶**，另一端叫**栈底**。

- 入栈（push）：放到栈顶
- 出栈（pop）：从栈顶拿走
- 特点：**后进先出（LIFO，Last In First Out）**

```
栈顶 top → [ 30 ]  ← 最后进来，最先出去
           [ 20 ]
栈底      [ 10 ]  ← 最先进来，最后出去
```

生活中的例子：一摞盘子、弹夹、浏览器后退。

### 2. 顺序栈（数组实现）

用一个数组 + 一个 `top` 指针就能实现。常见两种约定：

| 约定 | 空栈 | 入栈 | 出栈 |
|------|------|------|------|
| `top` 指向栈顶元素 | `top = -1` | `stack[++top] = x` | `x = stack[top--]` |
| `top` 指向栈顶的下一个空位 | `top = 0` | `stack[top++] = x` | `x = stack[--top]` |

```c
#define MAX 100
int stack[MAX];
int top = -1;          // 空栈

// 入栈
stack[++top] = x;

// 出栈
x = stack[top--];
```

**上溢和下溢**（题库常考）：

- 栈满还继续入栈 → **上溢（overflow）**
- 栈空还继续出栈 → **下溢（underflow）**

> 例：数组 `A[1..100]` 实现栈，`top` 初值为 0（表示空栈）。当 `top = 100` 时再入栈，数组已经满了，会发生**上溢**。

### 3. 链栈

用单链表实现，**栈顶放在链表头**，入栈/出栈都在头结点处做，所以还是 O(1)。

```
top → [ 30 | ● ] → [ 20 | ● ] → [ 10 | ∧ ]
```

- 优点：不用提前分配容量，不会上溢（除非内存不够）
- 缺点：每个结点多一个指针

### 4. 栈的常见应用

| 应用 | 为什么用栈 |
|------|------------|
| 括号匹配 | 后遇到的左括号要先匹配，正好后进先出 |
| 表达式求值 | 后缀表达式计算时，操作数后进先出 |
| 递归 / 函数调用 | 系统用栈保存返回地址、局部变量 |
| 撤销、浏览器后退 | 最近的操作最先撤销 |
| 图的深度优先搜索（DFS） | 一路走到底，再回退 |

**括号匹配**的做法：

```
遇到左括号 ( [ {  → 入栈
遇到右括号 ) ] }  → 看栈顶是不是对应的左括号
                   是 → 出栈
                   不是 / 栈空 → 不匹配
扫描结束 → 栈空才匹配
```

题库里的 `"({[]})"`：依次 push `(`、`{`、`[`，再依次 pop `[`、`{`、`(`，最后栈空，所以匹配。

### 5. 出栈序列怎么判断（题库常考）

入栈顺序固定是 `1, 2, 3, ..., n`，出栈顺序可以有很多种。判断一个序列是否合法，**用栈模拟**最稳妥：

```
按出栈序列一个一个看：
1. 如果下一个要输出的数还没入栈，就把它以及它前面的数依次入栈；
2. 此时栈顶必须正好是这个数，否则序列非法；
3. 弹出它，继续看下一个。
```

例：入栈 `1 2 3 4 5`，判断 `2 4 3 1 5`：

```
输出 2：push 1, push 2 → pop 2
输出 4：push 3, push 4 → pop 4
输出 3：栈顶是 3 → pop 3
输出 1：栈顶是 1 → pop 1
输出 5：push 5 → pop 5
全部成功 → 合法
```

再比如 `3 1 2`：输出 3 时 push 1、2、3，pop 3；下一个要输出 1，但栈顶是 2，非法。

> 规律：如果第一个输出的是 `n`，说明 1~n 全部入栈后才开始出栈，那么输出只能是 `n, n-1, ..., 1`，第 i 个输出就是 `n-i+1`。

## 二、队列（Queue）

### 1. 是什么

队列只允许在**队尾入队**、在**队头出队**。

- 入队（enqueue）：从队尾放进去
- 出队（dequeue）：从队头拿出来
- 特点：**先进先出（FIFO，First In First Out）**

```
队头 front                    队尾 rear
   ↓                             ↓
[ 10 ]  [ 20 ]  [ 30 ]  [    ]
  ↑ 出队                  ↑ 入队
```

生活中的例子：排队买饭、打印机任务、客服排队。

例：空队依次入队 1、2、3，出队两次，再入队 4 → 队列里剩下 `3, 4`。

### 2. 顺序队列的“假溢出”

用数组 + `front`、`rear` 实现队列时，每出队一个元素，`front` 就往后移动；每入队一个，`rear` 往后移动。

时间一长，`rear` 到了数组末尾，但数组前面还有空位——明明没满，却不能再入队了，这叫**假溢出**。

解决：把数组看成一个环，也就是**循环队列**。

### 3. 循环队列（重点）

规定：

- `front` 指向**队头元素**
- `rear` 指向**队尾的下一个位置**（下一个入队的位置）
- 数组大小是 `m`

```
下标:   0     1     2     3     4     5
      [     ][ 20 ][ 30 ][ 40 ][     ][     ]
              ↑front             ↑rear
front = 1，rear = 4，元素个数 = (4-1+6)%6 = 3
```

三个必须记住的公式：

| 状态 | 条件 |
|------|------|
| 队空 | `front == rear` |
| 队满 | `(rear + 1) % m == front` |
| 元素个数 | `(rear - front + m) % m` |

入队、出队：

```c
// 入队
Q[rear] = x;
rear = (rear + 1) % m;

// 出队
x = Q[front];
front = (front + 1) % m;
```

> 为什么队满要牺牲一个位置？因为如果不牺牲，队空和队满都会是 `front == rear`，没法区分。所以循环队列最多存 `m-1` 个元素。

**题库小例子 1**：大小为 5，初始 `front=0, rear=3`，两次出队 + 一次入队：

```
两次出队：front = (0+2)%5 = 2
一次入队：rear  = (3+1)%5 = 4
结果：front=2，rear=4
```

**题库小例子 2**：大小为 6，`rear=0, front=3`，删除两个元素 + 加入一个元素：

```
删除两个：front = (3+2)%6 = 5
加入一个：rear  = (0+1)%6 = 1
结果：rear=1，front=5
```

### 4. 链队列

用单链表实现队列：`front` 指向队头，`rear` 指向队尾。

```
front → [ 10 | ● ] → [ 20 | ● ] → [ 30 | ∧ ]
                                  ↑ rear
```

- 入队：在 `rear` 后面接一个新结点，`rear` 后移
- 出队：删掉 `front` 指向的结点，`front` 后移
- 复杂度都是 O(1)

**易错点**：队列里只有一个元素时出队，删完之后队列变空，`rear` 也要一起修改（题库里的“头、尾指针可能都要修改”）。

### 5. 队列的常见应用

| 应用 | 为什么用队列 |
|------|--------------|
| 广度优先搜索（BFS） | 一层一层往外扩展，先发现的先处理 |
| 任务调度 / 打印队列 | 先到先服务 |
| 缓冲区 | 数据先来先处理 |
| 树的层次遍历 | 按层访问，先入队的先出队 |
| 生产者-消费者 | 生产的东西排队等待消费 |

### 6. 两个栈模拟一个队列（题库常考）

思路：

- **S1 负责入队**：新元素直接 push 到 S1
- **S2 负责出队**：S2 不空时直接从 S2 pop
- 只有 **S2 为空**时，才把 S1 里的元素全部 pop 出来、push 进 S2（顺序刚好反过来）

例：入队 1、2、3，出队一次，再入队 4，再出队两次：

```
入队 1,2,3：S1 = [1,2,3]
出队一次：S2 为空 → 把 S1 倒入 S2 → S2 = [3,2,1]，pop 出 1
入队 4：S1 = [4]
再出队两次：S2 还有 [3,2] → 先 pop 2，再 pop 3
所以第二次出队的是 3
```

> 每个元素最多进 S1、进 S2、出 S2 各一次，均摊下来还是 O(1)。

## 三、栈 vs 队列

| 对比项 | 栈 | 队列 |
|--------|-----|------|
| 规则 | 后进先出（LIFO） | 先进先出（FIFO） |
| 插入/删除位置 | 同一端（栈顶） | 两端（队尾入、队头出） |
| 主要操作 | push / pop | enqueue / dequeue |
| 典型应用 | 递归、括号匹配、表达式求值、DFS | BFS、任务调度、缓冲区、层次遍历 |
| 核心操作复杂度 | O(1) | O(1)（循环队列） |

## 四、复杂度小结

| 结构 | 入 / 出 | 查找 | 空间 |
|------|---------|------|------|
| 顺序栈 | O(1) | O(n) | O(n) |
| 链栈 | O(1) | O(n) | O(n)，每个结点多一个指针 |
| 循环队列 | O(1) | O(n) | O(n)，最多存 m-1 个元素 |
| 链队列 | O(1) | O(n) | O(n)，每个结点多一个指针 |

> 栈和队列的插入/删除都在“端点”上操作，不需要移动其他元素，所以都是 O(1)。

## 五、考试易错点

1. 栈和队列都是**操作受限的线性表**，逻辑结构仍然是线性结构，只是插入/删除的位置被限制了。
2. 顺序栈 `top` 的初始值要看约定：`top=-1`（指向栈顶）和 `top=0`（指向下一个空位）的空栈/满栈判断不一样，别混用。
3. 栈满继续入栈是**上溢**，栈空继续出栈是**下溢**。
4. 循环队列三公式：
   - 空：`front == rear`
   - 满：`(rear + 1) % m == front`
   - 个数：`(rear - front + m) % m`
5. 循环队列要**牺牲一个位置**来区分空和满，所以数组大小是 m 时最多存 m-1 个元素。
6. 链队列删除最后一个元素时，`front` 和 `rear` 可能都要修改。
7. 递归改非递归、括号匹配、表达式求值用**栈**；BFS、层次遍历、任务调度用**队列**。
8. 出栈序列判断不要靠猜，直接用栈模拟：下一个要输出的数不是栈顶就继续入栈，入到 n 还不是栈顶就非法。
9. 两个栈模拟队列时，只有 **S2 为空**才能把 S1 倒进去；S2 不空时直接出 S2。

## 六、一句话总结

- **栈 = 一摞盘子**：后进先出，push/pop 都在栈顶。
- **队列 = 排队买饭**：先进先出，队尾入、队头出。
- **循环队列三公式**：空 `front==rear`；满 `(rear+1)%m==front`；个数 `(rear-front+m)%m`。
- **栈和队列的核心操作都是 O(1)**。
